# UI 设计迭代

[English](./README.md) | [简体中文](./README.zh-CN.md)

这是一个工作流技能，把 UI 从初稿带到评审完成：还没有设计时，拿一个现成的、设计良好的参考——用它公开的代码，或者保存它线上 demo 渲染出来的页面——把它的设计语言搬到页面需要的内容上；然后把它变成能用的真实页面，让人可以点选任意元素，把一句模糊的话变成单维度的 patch，并验证结果。

它不凭空发明页面长什么样。外观来自已经设计好的东西——用户选定的参考——优先来自用户自己偏好的来源，没有偏好时取自一份入门清单（shadcn/ui、Tremor、TailAdmin、Cruip、Astro themes、Vercel templates；One Page Love、Recent、Mobbin）——设计类技能或 agent、用户本人，或草稿所抽取自的线上产品。本技能负责复用或重建这份设计并让它可评审，从不根据一句话需求直接画页面。

交付物是一份**静态设计草稿**：一个目录，含一个 HTML 入口页面及其本地 CSS 与 JS，无需构建、无需联网即可在浏览器打开，可实时调整，可按元素逐个讨论。迁移到框架或模板语言不在范围内——草稿与设计契约才是迁移的起点。

## 它解决什么

AI 生成的界面有两个失败点，都与审美无关：

- **改不动。** 草稿是单一产物，"卡片收紧一点"会触发整块重写，用户既看不出改了什么，也保不住已经对的部分，下一轮继续漂移。
- **只能评审截图。** 静态图无法判断动效、反馈和状态，于是关于行为的所有决定都是盲做的，而弹窗、空态这些界面干脆不存在。

本技能用结构替代这两点：细节调整之前先把风格收进一小组 token；每个元素都可寻址；每次改动都是带明确目标的 patch；页面上任何可能出现的界面都可触发、可选中。

## 循环

| 阶段 | 目标 | 产物 |
| --- | --- | --- |
| 参照起草（没有设计时） | 用参考的设计语言承载你的内容 | `<name>.html`，lever 已绑定 |
| 接收 | 设计落到磁盘，token 绑定好 | `<name>.html`、一个 `:root` 块、`design-contract.md` |
| 让它能用 | 草稿像真页面一样有行为 | 草稿运行时 + 评审面板接入，服务已启动 |
| 迭代 | 改动可寻址、足够小 | 逐元素 patch，按 diff 评审 |
| 验收与交付 | 度量上限达标或已在契约中豁免，可迁移 | 草稿目录、契约、锚点表 |

## 安装

```bash
npx skills add https://git.nite07.com/nite/skills.git -g -s ui-design-iteration
```

附带的代码只需要一个能打开草稿的浏览器，以及运行草稿服务的 Python 3（仅标准库）。不安装任何其他依赖。

## 何时使用

- 设计已经定下来（由设计技能、用户或现有产品定），现在需要评审和迭代。
- 界面看起来是拼起来的：每个组件单看都不错，合起来不像一个产品。
- 需要把运行中应用的某个页面抽成静态、可检视的副本，用来讨论。
- 用户想自己动手调细节，而不是用语言描述。
- 还没有设计，最快的好起点是一个已经做得好的页面。

只有一句话需求时，本技能从参考页面起步而不是直接生成页面：先列出两三个候选，由用户挑选；用户也可以让 agent 代选，此时 agent 要说明理由，并在第一版草稿旁请用户确认。

## 用法

1. 还没有设计？先给页面分类，写出页面的论点（每个区块一条主张，以及真实存在的证据和图片），再从用户偏好的来源（没有偏好时用 `references/sources.md` 里的入门清单）挑两三个参考候选，让用户选定，研究并实测；写下它的设计语言，按内容规划区块，用这套语言复制、组合（只有截图时才重建）出每个区块（证据类内容绝不虚构），评审前先和参考并排比对（`references/drafting.md`）。已有设计则以单个 HTML 页面 + 真实文案的形式带进来（`references/intake.md`）。
2. 把十三个 lever 绑进一个 `:root` 块，替换掉与它们重复的字面值；如果草稿抽取自现有产品，则改为映射产品自己的 CSS 自定义属性。
3. 把 `templates/draft-kit.js` 复制到草稿旁边，用一个配置块和一个 script 标签接上。然后把草稿当页面用——菜单能开、弹窗能开、任何东西都不跳转。
4. 运行 `scripts/draft_server.py <draft-dir> <port>`，通过它打开草稿。
5. 打开选择模式（`P`）点任意元素；选区（CSS 选择器、所属组件、计算值、文字对比度、拖动过的滑杆、视口宽度）写入 `selection.json`，agent 直接读。想一次指出多处，就给每处加一条带备注的标记；标记在页面上编号显示，并写进同一个文件。
6. 每轮只改一个维度——密度、层次或冷暖——并说明允许动哪些 lever。
7. 评审这次改动，而不是整页：diff 碰到没要求的兄弟节点或 lever，就退回重做。
8. 收工前在每个状态、每个评审宽度下跑一遍审计——度量上限、对比度、焦点、键盘——然后去掉评审工具再交付草稿。

## 目录结构

```text
ui-design-iteration/
├── SKILL.md
├── references/
│   ├── drafting.md     # 参照起草：论点、设计语言、区块规划；复制或组合；比对
│   ├── sources.md      # 用户来源优先、如何判断任意来源、一份注明核实日期的入门清单
│   ├── intake.md       # 接收设计：要求什么、退回什么、如何映射到 lever
│   ├── tokens.md       # 十三个 lever、抽取自产品的草稿、外部组件、明暗主题
│   ├── live-draft.md   # 可用草稿的规则、草稿运行时、条件界面、抽取流程、验证
│   ├── panel.md        # 面板：配置、标记、对比度、审计、快照格式、服务、自动刷新
│   ├── iteration.md    # 如何使用选区与标记、每轮的规则、模糊反馈的分类
│   └── audit.md        # 默认度量上限、如何统计、可访问性、评审宽度、删除顺序
├── scripts/
│   └── draft_server.py      # 起服务并写入 selection.json（仅标准库）
├── templates/
│   ├── design-contract.md   # lever 及其来源、既定决定、锚点、交付清单
│   ├── draft-kit.js         # 评审面板：滑杆、点选、标记、对比度、审计、自动刷新（零依赖）
│   └── draft-kit.html       # 示例草稿：lever 块、锚点、运行时与面板的位置
├── LICENSE
├── README.md
└── README.zh-CN.md
```

## 它检查的度量上限

两种圆角、两种阴影、五种字号、两种字体族、零渐变、每页一个卡片网格、一个带动效的组件、不用标题上方的小标签（eyebrow）、不用每项顶部放图标的功能列表。其中五项参考了一份对 247 个画廊站点的外部研究，本技能未复现该研究；`references/audit.md` 标明了是哪几项。

这些是迭代的默认出口条件，不是风格指南：设计契约里记录的决定可以覆盖其中任何一条；本技能指出"这页像拼的"，但不会替你重做设计。

可访问性同时检查，且不可豁免：WCAG 2 AA 文字对比度（面板对每个渲染出的文字元素计算）、焦点可见、键盘可操作、触控目标尺寸，并且在每个评审宽度下都要检查。
